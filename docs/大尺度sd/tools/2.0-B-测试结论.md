# Seedance 2.0-B 上游直连测试结论

脚本：`seedance-2.0-B.sh`（本目录）
基址：`http://106.54.45.168/seedance-gateway`（与 `海外sd73` 同一上游）
测试时间：2026-10-10

## 结论：`seedance-2.0-B` 在上游不可用

**`seedance-2.0-B-720p` / `-1080p` 提交必然返回 HTTP 400**，与请求格式无关：

```
HTTP 400
{"error":{"code":"invalid_request",
          "message":"The request contains invalid or unsupported parameters."}}
```

### 证据一：模型 × 格式矩阵

`./seedance-2.0-B.sh matrix` 实测（每格独立幂等键）：

| 模型 | content | prompt | metadata |
|---|---|---|---|
| `seedance-2.0-mini-720p` | **200** | **200** | 400 |
| `seedance-2.0-720p` | **200** | **200** | 400 |
| `seedance-2.5-720p` | **200** | **200** | 400 |
| `seedance-2.0-B-720p` | 400 | 400 | 400 |
| `seedance-2.0-B-1080p` | 400 | 400 | 400 |
| `seedance-2.0-C-720p` | 400 | 400 | 400 |

同为 400 的 `metadata` 列说明该字段本身不被接受（`metadata` 是 `海外sd73`/Dreamina 的写法，
不是 `大尺度sd`/`海外sd` 的写法），但 **`2.0-B`/`2.0-C` 连正确的 `content`、`prompt` 格式也拒绝**。

### 证据二：模型名变体全部失败

`seedance-2.0-B-720p`、`seedance-2.0-B`、`seedance-2.0-b-720p`、
`Seedance-2.0-B-720p`、`seedance-2.0-B-480p` —— 全部 400。

### 证据三：路径无关

| 路径 | `2.0-720p` | `2.0-B-720p` |
|---|---|---|
| `POST /v1/videos` | 200 | 400 |
| `POST /seedance/api/v3/contents/generations/tasks` | 200 | 400 |
| `POST /v1/video/generations`（海外sd73 写法） | — | 404* |

\* `海外sd73` 的 `/v1/video/generations` 在本基址下不存在，须用 `/v1/videos`。

## 上游对 2.0-B 的自述

`GET /seedance/capabilities` 中：

```json
{"id":"seedance-2.0-B-720p","resolution":"720p",
 "production_verified":false,"reference_support":"unverified"}
```

`POST /seedance/media/preflight` 对 `2.0-B-720p` 返回：

```json
{"compatibility":"unverified",
 "checks":[...,{"name":"model_reference_support","status":"unverified",
                "code":"model_capability_unverified"}],
 "production_verified":false}
```

即上游明确标注：**2.0-B 的模型能力未验证**。模型出现在 `/v1/models` 目录里，
但不代表可提交——这与文档「列表不代表生成验收结果」一致。**所有模型**的
`production_verified` 都是 `false`，因此该字段不能区分可用/不可用；
真正的判据是实际提交能否返回 200。

## 已验证可用的完整链路

用 `seedance-2.0-720p` 跑通了全流程，证明脚本与网关正常：

1. `POST /seedance/media/upload`（Content-Type 必须是真实 MIME，如 `image/png`）
   → 返回 `id` + `asset_uri`，`status=queued`
2. `POST /seedance/media` `{action:"get"}` 轮询 → `running` → **`succeeded`**
3. `POST /seedance/media/preflight` → 各 check 均 `supported`（`model_reference_support` 为 `unverified`）
4. `POST /v1/videos` + `content[].image_url.url = asset://task_...` + `role: reference_image`
   → **HTTP 200，返回 task_id**
5. `GET /v1/videos/{id}` 轮询 → `completed`，`GET .../content` 下载到真实 MP4（1.6 MB，

   `ISO Media, MP4 Base Media v1`）

## 踩过的坑（脚本已处理）

| 现象 | 原因 | 处理 |
|---|---|---|
| `HTTP 415 unsupported_media_type` | 上传时用了 `application/octet-stream` | 必须按文件真实类型传 `image/png` 等 |
| `HTTP 409 idempotency_conflict` | 幂等键重复 | 每次请求生成唯一键 |
| `HTTP 404 not_found`（`/v1/video/generations`） | 那是 `海外sd73` 文档的路径 | 本网关用 `/v1/videos` |
| 素材 `failed` | 64×64 小图被判失败；512×512 成功 | 用真实尺寸图片 |

## 建议

**`2.0-B` 是平台侧未开放，不是脚本或参数问题。** 请向平台确认：

1. `2.0-B` 是否需要白名单/专属分组才能调用；
2. 是否需要特定的请求格式（目前 3 种主流格式全部被拒）；
3. 该模型是否仅对特定账户开放。

在平台明确前，**`seedance-2.0-B-720p` 无法用于生产**。
如必须使用，先用 `seedance-2.0-720p` 或 `seedance-2.5-720p` 替代。

## 计费提示

`matrix` 命令的每个 200 都会创建**计费任务**。排查过程中已产生多个
`seedance-2.0-*` 任务（`2.0-B` 的 400 不创建任务、不计费）。
请核对消费记录；终态任务可用 `DELETE /v1/videos/{id}` 隐藏（不退款）。
