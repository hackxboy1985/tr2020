# 架构设计：多上游适配方案

## 📋 概述

本文档描述 new-api 如何支持多种下游接口格式和多个上游服务商的架构设计。

---

## 🎯 业务需求

### 下游用户接口

new-api 需要支持两种下游接口格式：

1. **OpenAI 兼容格式**（现有用户使用）
   - 路径风格：`/v1/videos`, `/v1/video/generations`
   - 现有用户习惯使用
   
2. **火山官方格式**（新增支持）
   - 路径风格：`/api/v3/contents/generations/tasks`, `/?Action=XXX`
   - 使用火山引擎的路径和参数风格
   - **注意**：这里"火山官方格式"指的是接口风格，不代表后端一定连接火山官方服务

### 上游服务商

无论下游用户使用哪种格式，new-api 都可以将请求转发到任意上游服务商：

1. **咪咕中转站**（当前在用）
   - 视频接口支持火山格式路径
   - 素材接口使用 RESTful 格式
   
2. **火山官方**（未来）
   - 完全兼容火山格式
   
3. **其他中转站**（未来扩展）
   - 根据各家 API 格式进行适配

**关键点**：下游接口格式与上游服务商解耦，用户无需关心后端连接的是哪家服务商。

## 🔧 技术实现

### 渠道配置参数

在渠道的 `other_settings` 中新增 `SeedanceAssetAPIFormat` 字段：

```json
{
  "id": 1,
  "type": 54,
  "name": "咪咕中转站",
  "base_url": "https://sd.dawnloadai.com:8443",
  "other_settings": {
    "seedance_asset_base_url": "https://sd.dawnloadai.com:9444",
    "seedance_asset_api_format": "gatewayMg"
  }
}
```

| 配置值 | 说明 | 上游格式 |
|--------|------|----------|
| `official` | 火山官方 | Action 参数风格 `/?Action=XXX` |
| `gatewayMg` | 咪咕中转站 | RESTful 风格 `/api/seedance/proxy/...` |
| 空或未配置 | 默认 | 使用 `gatewayMg` |

### Action → RESTful 映射逻辑

`controller/relay_asset.go` 中实现 Action 到 RESTful 的转换：

```go
func convertActionToGatewayMg(baseURL, action string, bodyBytes []byte) (method, url string, newBody []byte, err error) {
    // 解析请求体，提取 ID 参数
    var reqBody map[string]interface{}
    json.Unmarshal(bodyBytes, &reqBody)
    
    switch action {
    case "CreateAssetGroup":
        return "POST", baseURL + "/api/seedance/proxy/assets/groups", bodyBytes, nil
        
    case "ListAssetGroups":
        // GET 请求，query 参数从 body 转为 URL query
        query := buildQueryFromBody(reqBody)
        return "GET", baseURL + "/api/seedance/proxy/assets/groups?" + query, nil, nil
        
    case "GetAssetGroup":
        groupID := reqBody["GroupId"].(string)
        return "GET", fmt.Sprintf("%s/api/seedance/proxy/assets/groups/%s", baseURL, groupID), nil, nil
        
    case "UpdateAssetGroup":
        groupID := reqBody["GroupId"].(string)
        return "PUT", fmt.Sprintf("%s/api/seedance/proxy/assets/groups/%s", baseURL, groupID), bodyBytes, nil
        
    case "DeleteAssetGroup":
        groupID := reqBody["GroupId"].(string)
        return "DELETE", fmt.Sprintf("%s/api/seedance/proxy/assets/groups/%s", baseURL, groupID), nil, nil
        
    // ... 素材接口类似
    }
}
```

## 🔄 请求流程

### 视频生成流程

```
下游用户
   ↓
调用 new-api 接口（两种格式任选）
├─ OpenAI 格式: POST /v1/videos
└─ 火山格式: POST /api/v3/contents/generations/tasks
   ↓
new-api 中间层
├─ middleware.Distribute() 选择渠道
└─ controller.RelayTask 处理请求
   ↓ 统一转换为火山格式
   ↓
根据渠道配置转发到上游（任意一家）
├─ 咪咕中转站: https://sd.dawnloadai.com:8443/api/v3/... ✅ (当前)
├─ 火山官方: https://ark.cn-beijing.volces.com/api/v3/... (未来)
└─ 其他中转站: ... (未来)
```

**说明**：
- 用户使用"火山格式"接口 ≠ 后端连接火山官方
- 当前用户调用火山格式接口，实际转发到咪咕中转站
- 咪咕中转站支持火山格式的路径和字段

### Asset API 流程

```
下游用户
   ↓
调用火山 Action 风格接口
POST /api/seedance/assets/v2/?Action=CreateAssetGroup
   ↓
new-api 中间层
├─ middleware.TokenAuth() 验证
└─ controller.RelayAsset 处理请求
   ↓
读取渠道配置的 seedance_asset_api_format
   ↓
┌─────────────────────────────────────────┐
│ 如果是 gatewayMg (咪咕中转站):          │
│   ↓ 转换为 RESTful 格式                 │
│   POST https://sd.dawnloadai.com:9444   │
│        /api/seedance/proxy/assets/groups│
│                                          │
│ 如果是 official (火山官方):             │
│   ↓ 保持 Action 格式                    │
│   POST https://ark.cn-beijing.volces.com│
│        /?Action=CreateAssetGroup&...    │
└─────────────────────────────────────────┘
```

**说明**：
- 下游统一使用 Action 格式（`/?Action=XXX`）
- 上游根据配置选择不同的转发格式：
  - `gatewayMg`：转换为咪咕的 RESTful 格式
  - `official`：保持 Action 格式（适用于火山官方及兼容火山格式的中转站）

## ✅ 优势

1. **下游接口统一**：用户只需要使用火山官方格式，无需关心上游差异
2. **上游灵活切换**：通过渠道配置切换不同上游，无需修改代码
3. **易于扩展**：新增上游服务商只需添加新的格式转换逻辑
4. **向后兼容**：现有老接口不受影响
