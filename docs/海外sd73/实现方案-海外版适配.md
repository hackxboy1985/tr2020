# Dreamina Seedance 海外版适配实现方案

**文档版本**：v1.0  
**创建日期**：2026-09-12  
**适用场景**：支持海外版 Dreamina Seedance 2.0 API（`http://106.54.45.168`）

---

## 一、背景说明

### 1.1 现状

当前 `relay/channel/task/doubao/adaptor.go` 支持两种上游格式：

| `asset_upstream_version` | 上游类型 | 创建路径 | 查询路径 | 响应格式 |
|--------------------------|----------|----------|----------|----------|
| `gateway` (默认) | Seedance Gateway (port 9444) | `/api/v3/contents/generations/tasks` | `/api/v3/contents/generations/tasks/{id}` | 直接返回任务对象 |
| `kwjm` | KWJM 上游 | `/v1/videos/generations` | `/v1/videos/generations/{id}` | 直接返回任务对象 |

两者的响应格式都是**直接返回任务对象**，例如：

```json
{
  "id": "cgt-xxx",
  "model": "doubao-seedance-2-0-260128",
  "status": "succeeded",
  "content": {
    "video_url": "https://..."
  },
  "usage": {...}
}
```

### 1.2 海外版差异

海外版 `http://106.54.45.168` 是一个**网关平台**（BytePlus ModelArk），其响应格式完全不同：

#### 创建任务响应（兼容）
```json
{
  "id": "task_xxx",
  "task_id": "task_xxx",
  "object": "video",
  "model": "dreamina-seedance-2-0-260128",
  "status": "queued",
  "progress": 0,
  "created_at": 1786681030
}
```
✅ 此格式与现有代码兼容，无需修改。

#### 查询任务响应（不兼容）
```json
{
  "code": "success",
  "message": "",
  "data": {
    "id": 21,
    "task_id": "task_KPxsbZc6x2znnrk8vbRm359optsYdtx4",
    "channel_id": 2,
    "action": "generate",
    "status": "SUCCESS",                    // 外层状态（大写）
    "progress": "100%",
    "result_url": "https://...",            // 直接的视频地址
    "fail_reason": "",
    "quota": 943346,
    "submit_time": 1786681030,
    "start_time": 1786681049,
    "finish_time": 1786681170,
    "data": {                               // 内层嵌套的真实任务数据
      "id": "cgt-20260814121710-wc794",
      "model": "dreamina-seedance-2-0-260128",
      "resolution": "1080p",
      "ratio": "16:9",
      "duration": 5,
      "seed": 72072,
      "framespersecond": 24,
      "output_format": "mp4",
      "generate_audio": true,
      "usage": {
        "total_tokens": 245025,
        "completion_tokens": 245025
      },
      "status": "succeeded",                // 内层状态（小写）
      "content": {
        "video_url": "https://..."
      }
    }
  }
}
```

❌ **关键差异**：
1. 外层包装：`{code, message, data}` 三层结构
2. 嵌套的 `data.data`：真正的任务详情在第二层 `data` 中
3. 状态值：外层 `SUCCESS`（大写），内层 `succeeded`（小写）
4. 视频地址：既有 `data.result_url`，又有 `data.data.content.video_url`

## 二、设计方案：适配器模式

### 2.1 设计原则

**核心原则**：
- ✅ **不修改现有逻辑**：保持 `gateway` 和 `kwjm` 的现有行为不变
- ✅ **扩展性**：通过配置区分不同上游格式
- ✅ **隔离性**：新增代码与现有代码隔离，降低风险
- ✅ **向后兼容**：现有渠道配置无需修改

### 2.2 配置方案

新增 `asset_upstream_version` 值：`overseas` 或 `byteplus`

| 配置值 | 说明 | 创建路径 | 查询路径 | 响应格式解析器 |
|--------|------|----------|----------|----------------|
| `gateway` | Seedance Gateway (默认) | `/api/v3/contents/generations/tasks` | `/api/v3/contents/generations/tasks/{id}` | `parseTaskResultDirect` |
| `kwjm` | KWJM 上游 | `/v1/videos/generations` | `/v1/videos/generations/{id}` | `parseTaskResultDirect` |
| **`overseas`** ⭐ | **海外版网关** | `/v1/video/generations` | `/v1/video/generations/{id}` | **`parseTaskResultOverseas`** ⭐ |

```go
// parser.go - 响应解析器接口
package doubao

import (
	"github.com/QuantumNous/new-api/model"
	relaycommon "github.com/QuantumNous/new-api/relay/common"
)

// TaskResponseParser 定义任务响应解析器接口
type TaskResponseParser interface {
	// Parse 解析上游响应体，返回标准化的任务信息
	Parse(respBody []byte) (*relaycommon.TaskInfo, error)
}

// DirectParser 直接解析响应体（适用于 gateway 和 kwjm）
type DirectParser struct{}

func (p *DirectParser) Parse(respBody []byte) (*relaycommon.TaskInfo, error) {
	// 现有的 ParseTaskResult 逻辑
	resTask := responseTask{}
	if err := common.Unmarshal(respBody, &resTask); err != nil {
		return nil, errors.Wrap(err, "unmarshal task result failed")
	}
	
	// ... 现有的状态映射逻辑 ...
}

// OverseasParser 解析海外版包装响应体
type OverseasParser struct{}

// OverseasResponse 海外版响应结构
type OverseasResponse struct {
	Code    string `json:"code"`    // "success" / "error"
	Message string `json:"message"`
	Data    struct {
		ID         int    `json:"id"`
		TaskID     string `json:"task_id"`
		ChannelID  int    `json:"channel_id"`
		Action     string `json:"action"`
		Status     string `json:"status"`      // 外层状态：SUCCESS / FAILED / NOT_START / IN_PROGRESS
		Progress   string `json:"progress"`
		ResultURL  string `json:"result_url"`  // 直接的视频地址
		FailReason string `json:"fail_reason"`
		Quota      int64  `json:"quota"`
		SubmitTime int64  `json:"submit_time"`
		StartTime  int64  `json:"start_time"`
		FinishTime int64  `json:"finish_time"`
		Data       struct {
			// 内层：标准的 Ark 任务结构
			ID              string `json:"id"`    // 上游真实任务 ID，如 cgt-xxx
			Model           string `json:"model"`
			Resolution      string `json:"resolution"`
			Ratio           string `json:"ratio"`
			Duration        int    `json:"duration"`
			Seed            int    `json:"seed"`
			FramesPerSecond int    `json:"framespersecond"`
			OutputFormat    string `json:"output_format"`
			GenerateAudio   bool   `json:"generate_audio"`
			Usage           struct {
				TotalTokens      int `json:"total_tokens"`
				CompletionTokens int `json:"completion_tokens"`
			} `json:"usage"`
			Status  string `json:"status"` // 内层状态：succeeded / failed / pending
			Content struct {
				VideoURL string `json:"video_url"`
			} `json:"content"`
		} `json:"data"`
	} `json:"data"`
}

func (p *OverseasParser) Parse(respBody []byte) (*relaycommon.TaskInfo, error) {
	var overseasResp OverseasResponse
	if err := common.Unmarshal(respBody, &overseasResp); err != nil {
		return nil, errors.Wrap(err, "unmarshal overseas response failed")
	}

	// 检查顶层错误
	if overseasResp.Code != "success" && overseasResp.Code != "" {
		return nil, errors.Errorf("overseas api error: code=%s, message=%s", 
			overseasResp.Code, overseasResp.Message)
	}

	taskResult := relaycommon.TaskInfo{
		Code:      0,
		OriTaskID: overseasResp.Data.Data.ID, // 内层的上游任务 ID
	}

	// 优先使用外层状态（大写），映射到内部状态
	switch overseasResp.Data.Status {
	case "NOT_START":
		taskResult.Status = model.TaskStatusQueued
		taskResult.Progress = "10%"
	case "IN_PROGRESS":
		taskResult.Status = model.TaskStatusInProgress
		taskResult.Progress = overseasResp.Data.Progress
		if taskResult.Progress == "" {
			taskResult.Progress = "50%"
		}
	case "SUCCESS":
		taskResult.Status = model.TaskStatusSuccess
		taskResult.Progress = "100%"
		// 优先使用外层的 result_url
		taskResult.Url = overseasResp.Data.ResultURL
		if taskResult.Url == "" {
			// 回退到内层的 video_url
			taskResult.Url = overseasResp.Data.Data.Content.VideoURL
		}
		// 使用内层的 usage 信息用于计费
		taskResult.CompletionTokens = overseasResp.Data.Data.Usage.CompletionTokens
		taskResult.TotalTokens = overseasResp.Data.Data.Usage.TotalTokens
	case "FAILED":
		taskResult.Status = model.TaskStatusFailure
		taskResult.Progress = "100%"
		taskResult.Reason = overseasResp.Data.FailReason
	default:
		// 未知状态，尝试使用内层状态（小写）
		innerStatus := overseasResp.Data.Data.Status
		switch innerStatus {
		case "pending", "queued":
			taskResult.Status = model.TaskStatusQueued
			taskResult.Progress = "10%"
		case "processing", "running":
			taskResult.Status = model.TaskStatusInProgress
			taskResult.Progress = "50%"
		case "succeeded":
			taskResult.Status = model.TaskStatusSuccess
			taskResult.Progress = "100%"
			taskResult.Url = overseasResp.Data.Data.Content.VideoURL
			taskResult.CompletionTokens = overseasResp.Data.Data.Usage.CompletionTokens
			taskResult.TotalTokens = overseasResp.Data.Data.Usage.TotalTokens
		case "failed":
			taskResult.Status = model.TaskStatusFailure
			taskResult.Progress = "100%"
			taskResult.Reason = overseasResp.Data.FailReason
		default:
			// 完全未知，标记为处理中
			taskResult.Status = model.TaskStatusInProgress
			taskResult.Progress = "30%"
		}
	}

	return &taskResult, nil
}
```

```go
func (a *TaskAdaptor) Init(info *relaycommon.RelayInfo) {
	// ... 现有初始化逻辑 ...

	// 根据 asset_upstream_version 选择解析器
	upstreamVersion := settings.AssetUpstreamVersion
	if upstreamVersion == "" {
		upstreamVersion = "gateway" // 默认
	}

	switch upstreamVersion {
	case "overseas", "byteplus":
		// 海外版：使用包装格式解析器
		a.responseParser = &OverseasParser{}
		if a.videoGeneratePath == "" {
			a.videoGeneratePath = "/v1/video/generations"
		}
		if a.videoFetchPath == "" {
			a.videoFetchPath = "/v1/video/generations"
		}
		common.SysLog("[Init] 使用海外版解析器 (OverseasParser)")
	case "kwjm":
		// KWJM：使用直接解析器
		a.responseParser = &DirectParser{}
		if a.videoGeneratePath == "" {
			a.videoGeneratePath = "/v1/videos/generations"
		}
		if a.videoFetchPath == "" {
			a.videoFetchPath = "/v1/videos/generations"
		}
		common.SysLog("[Init] 使用直接解析器 (DirectParser) - KWJM")
	case "gateway":
		fallthrough
	default:
		// Gateway（默认）：使用直接解析器
		a.responseParser = &DirectParser{}
		if a.videoGeneratePath == "" {
			a.videoGeneratePath = "/api/v3/contents/generations/tasks"
		}
		if a.videoFetchPath == "" {
			a.videoFetchPath = "/api/v3/contents/generations/tasks"
		}
		common.SysLog("[Init] 使用直接解析器 (DirectParser) - Gateway")
	}
}
```

```go
func (a *TaskAdaptor) ParseTaskResult(respBody []byte) (*relaycommon.TaskInfo, error) {
	if a.responseParser == nil {
		common.SysLog("[ParseTaskResult] WARNING: responseParser 未初始化，使用默认 DirectParser")

	}
	
	taskInfo, err := a.responseParser.Parse(respBody)
	if err != nil {
		// 记录原始响应体，方便排查

			string(respBody), err))
	}
	return taskInfo, err
}
```

## 八、FAQ

### Q1: 为什么不直接修改现有的 ParseTaskResult？
**A**: 海外版的响应格式差异较大（三层包装），直接修改会引入大量 if-else 分支，增加现有逻辑的复杂度和出错风险。使用适配器模式可以：
- 隔离变更范围
- 便于测试和维护
- 易于扩展（未来支持更多上游格式）

### Q2: 如果上游 API 格式再次变更怎么办？
**A**: 可以继续新增解析器，例如 `OverseasParserV2`，通过配置 `asset_upstream_version=overseas_v2` 来使用新版本解析器，旧版本继续使用 `OverseasParser`。

### Q3: 海外版和国内版可以共存吗？
**A**: 完全可以。它们通过不同的渠道配置区分：
- 国内版：BaseURL 指向国内网关，`asset_upstream_version=gateway`
- 海外版：BaseURL 指向 `http://106.54.45.168`，`asset_upstream_version=overseas`

### Q4: 是否需要修改下游用户的请求格式？
**A**: 不需要。下游用户统一使用 OpenAI 格式请求（`POST /v1/video/generations`），网关自动根据渠道配置转换成对应的上游格式。
