# 模型映射 V2 设计文档

## 概述

模型映射 V2 在保持 V1 向后兼容的基础上，增加了基于请求参数的条件映射功能。支持根据请求中的参数值（如 `temperature`、`max_tokens`、嵌套字段等）动态选择目标模型。

## 版本对比

### V1 - 简单键值映射（当前版本）

```json
{
  "gpt-4": "gpt-4-turbo",
  "claude-3": "claude-3-sonnet"
}
```

**特点**：
- 简单的模型名到模型名的映射
- 支持链式映射：`model_a -> model_b -> model_c`
- 有循环检测机制

### V2 - 条件规则映射（新版本）

```json
{
  "version": 2,
  "rules": [
    {
      "source_model": "gpt-4",
      "conditions": [
        {
          "param": "temperature",
          "operator": ">",
          "value": 0.8
        }
      ],
      "target_model": "gpt-4-turbo",
      "priority": 1
    }
  ],
  "fallback": {
    "gpt-4": "gpt-4o"
  }
}
```

**特点**：
- 支持基于参数的条件匹配
- 支持多层次参数路径（如 `response_format.type`）
- 优先级控制
- fallback 机制
- 完全向后兼容 V1

## V2 配置格式详解

### 完整配置示例

```json
{
  "version": 2,
  "rules": [
    {
      "source_model": "gpt-4",
      "conditions": [
        {
          "param": "temperature",
          "operator": ">",
          "value": 0.8
        },
        {
          "param": "max_tokens",
          "operator": ">=",
          "value": 4000
        }
      ],
      "target_model": "gpt-4-turbo",
      "priority": 1,
      "description": "高温度+长输出场景使用 turbo"
    },
    {
      "source_model": "gpt-4",
      "conditions": [
        {
          "param": "response_format.type",
          "operator": "==",
          "value": "json_object"
        }
      ],
      "target_model": "gpt-4-turbo-preview",
      "priority": 2,
      "description": "JSON 输出场景"
    },
    {
      "source_model": "claude-3",
      "conditions": [
        {
          "param": "web_search_options.enabled",
          "operator": "==",
          "value": true
        }
      ],
      "target_model": "claude-3-opus",
      "priority": 1
    },
    {
      "source_model": "gemini-pro",
      "conditions": [
        {
          "param": "extra_body.generationConfig.temperature",
          "operator": "<",
          "value": 0.3
        }
      ],
      "target_model": "gemini-pro-latest",
      "priority": 1
    },
    {
      "source_model": "gpt-3.5-turbo",
      "conditions": [
        {
          "param": "stream",
          "operator": "==",
          "value": false
        }
      ],
      "target_model": "gpt-3.5-turbo-instruct"
    }
  ],
  "fallback": {
    "gpt-4": "gpt-4o",
    "claude-3": "claude-3-sonnet",
    "gemini-pro": "gemini-1.5-pro"
  }
}
```

### 字段说明

#### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | number | 是 | 固定为 `2`，标识使用 V2 规则引擎 |
| `rules` | array | 是 | 规则列表，按优先级匹配 |
| `fallback` | object | 否 | 当所有规则都不匹配时使用的简单映射（V1 格式） |

#### Rule 对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source_model` | string | 是 | 源模型名（用户请求的模型） |
| `conditions` | array | 否 | 条件列表，**所有条件必须同时满足**（AND 逻辑） |
| `target_model` | string | 是 | 目标模型名（映射后的模型） |
| `priority` | number | 否 | 优先级，数值越小优先级越高，默认 999 |
| `description` | string | 否 | 规则描述，仅用于文档说明 |

#### Condition 对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `param` | string | 是 | 参数路径，支持点号分隔的多层路径 |
| `operator` | string | 是 | 比较运算符：`>`, `>=`, `<`, `<=`, `==`, `!=`, `in`, `not_in` |
| `value` | any | 是 | 比较值，类型需与参数类型匹配 |

## 参数路径（param）

### 支持的路径格式

使用点号（`.`）分隔的多层路径，例如：

- **一级参数**：`temperature`、`max_tokens`、`stream`
- **二级参数**：`response_format.type`、`stream_options.include_usage`
- **三级及以上**：`extra_body.generationConfig.temperature`、`web_search_options.max_results`

### 常用参数路径示例

根据 `dto/openai_request.go` 中的定义：

#### 一级参数

```json
{
  "param": "temperature",        // *float64
  "param": "max_tokens",         // *uint
  "param": "top_p",              // *float64
  "param": "top_k",              // *int
  "param": "stream",             // *bool
  "param": "frequency_penalty",  // *float64
  "param": "presence_penalty",   // *float64
  "param": "n",                  // *int
  "param": "reasoning_effort"    // string
}
```

#### 二级参数（结构体字段）

```json
{
  "param": "response_format.type",           // string: "text", "json_object"
  "param": "stream_options.include_usage",   // *bool
  "param": "web_search_options.enabled"      // *bool (Claude)
}
```

#### 三级参数（嵌套 JSON）

对于 `json.RawMessage` 类型的字段（如 `extra_body`），需要先解析 JSON：

```json
{
  "param": "extra_body.generationConfig.temperature",
  "param": "extra_body.imageConfig.size",
  "param": "search_parameters.max_results"
}
```

### 参数类型对应

| Go 类型 | JSON 类型 | 示例值 |
|---------|----------|--------|
| `*float64` | number | `0.8`, `1.5` |
| `*uint`, `*int` | number | `100`, `4000` |
| `*bool` | boolean | `true`, `false` |
| `string` | string | `"json_object"`, `"gpt-4"` |
| `json.RawMessage` | 需解析 | 递归解析嵌套字段 |

## 运算符（operator）

### 数值比较

| 运算符 | 说明 | 示例 | value 必填 |
|--------|------|------|-----------|
| `>` | 大于 | `temperature > 0.8` | 是 |
| `>=` | 大于等于 | `max_tokens >= 4000` | 是 |
| `<` | 小于 | `temperature < 0.3` | 是 |
| `<=` | 小于等于 | `top_p <= 0.5` | 是 |

### 等值比较

| 运算符 | 说明 | 示例 | value 必填 |
|--------|------|------|-----------|
| `==` | 等于 | `stream == false` | 是 |
| `!=` | 不等于 | `response_format.type != "text"` | 是 |


### 集合运算

| 运算符 | 说明 | 示例 | value 必填 |
|--------|------|------|-----------|
| `in` | 值在集合中 | `reasoning_effort in ["low", "medium"]` | 是（数组） |
| `not_in` | 值不在集合中 | `model not_in ["gpt-3.5-turbo"]` | 是（数组） |

### 参数不存在时的行为

**核心原则**：用户不传某个字段 → 该字段的所有条件直接跳过（条件判断为 false）

**示例**：
```json
{
  "source_model": "gpt-4",
  "conditions": [
    {"param": "temperature", "operator": ">", "value": 0.8},
    {"param": "max_tokens", "operator": ">=", "value": 4000}
  ],
  "target_model": "gpt-4-turbo"
}
```

**场景分析**：

| 请求参数 | 条件1（temperature > 0.8） | 条件2（max_tokens >= 4000） | 规则匹配 |
|---------|--------------------------|---------------------------|---------|
| `{temperature: 0.9, max_tokens: 5000}` | ✓ (0.9 > 0.8) | ✓ (5000 >= 4000) | ✓ 匹配 |
| `{temperature: 0.9}` | ✓ (0.9 > 0.8) | ✗ (max_tokens 不存在) | ✗ 不匹配 |
| `{max_tokens: 5000}` | ✗ (temperature 不存在) | ✓ (5000 >= 4000) | ✗ 不匹配 |
| `{}` | ✗ (temperature 不存在) | ✗ (max_tokens 不存在) | ✗ 不匹配 |

**注意**：所有 conditions 必须同时满足（AND 逻辑），任何一个条件失败（包括参数不存在）都会导致整个规则不匹配。

## 匹配逻辑

### 规则匹配流程

1. **版本检测**
   - 如果 JSON 包含 `"version": 2` → 使用 V2 引擎
   - 否则 → 使用 V1 简单映射（向后兼容）

2. **规则过滤**
   - 从 `rules` 中筛选出 `source_model` 匹配的规则

3. **优先级排序**
   - 按 `priority` 升序排序（数值越小优先级越高）
   - 相同 priority 时按定义顺序

4. **条件匹配**
   - 遍历排序后的规则
   - 检查每个规则的所有 `conditions`
   - **所有条件必须同时满足**（AND 逻辑）

5. **返回结果**
   - 匹配成功 → 返回 `target_model`
   - 所有规则都不匹配 → 查找 `fallback` 中的映射
   - fallback 也没有 → 返回原 `source_model`

6. **链式映射与循环检测**
   - **V2 不支持链式映射**：每次映射只执行一轮，不会将 `target_model` 再次作为 `source_model` 查找
   - **循环检测范围**：检测 V2 rules + fallback 的全局循环
   - **检测时机**：配置加载时预检测，运行时不再检测

### 链式映射策略

**V1 行为**（当前实现）：
```json
{
  "gpt-4": "gpt-4-turbo",
  "gpt-4-turbo": "gpt-4-custom"
}
```
- 支持链式：`gpt-4 → gpt-4-turbo → gpt-4-custom`
- 有循环检测

**V2 行为**（新设计）：
```json
{
  "version": 2,
  "rules": [
    {"source_model": "gpt-4", "target_model": "gpt-4-turbo"}
  ],
  "fallback": {
    "gpt-4-turbo": "gpt-4-custom"
  }
}
```
- **不支持链式映射**：映射一次后立即返回
- 原因：条件映射的复杂性使链式映射难以理解和调试
- 如果需要链式效果，需要在配置中直接写最终目标模型

**混合场景示例**：

场景1：V2 rules + fallback 无循环
```json
{
  "version": 2,
  "rules": [
    {"source_model": "gpt-4", "target_model": "gpt-4-turbo"}
  ],
  "fallback": {
    "claude-3": "claude-3-sonnet"
  }
}
```
✓ 合法：`gpt-4 → gpt-4-turbo`（结束）

场景2：V2 rules + fallback 存在循环
```json
{
  "version": 2,
  "rules": [
    {"source_model": "gpt-4", "target_model": "gpt-4-turbo"}
  ],
  "fallback": {
    "gpt-4-turbo": "gpt-4"
  }
}
```
✗ 配置错误：形成循环 `gpt-4 → gpt-4-turbo → gpt-4`（虽然不会执行，但配置本身有歧义）

场景3：V2 rules 内部循环
```json
{
  "version": 2,
  "rules": [
    {"source_model": "gpt-4", "target_model": "gpt-4-turbo"},
    {"source_model": "gpt-4-turbo", "target_model": "gpt-4"}
  ]
}
```
✗ 配置警告：虽然不会执行链式，但配置存在潜在循环，建议修改

### 循环检测算法

在配置加载时执行：

```go
func ValidateMappingConfig(config *MappingConfigV2) error {
    // 构建映射图（包括 rules 和 fallback）
    mappingGraph := make(map[string][]string)
    
    // 添加 rules
    for _, rule := range config.Rules {
        mappingGraph[rule.SourceModel] = append(
            mappingGraph[rule.SourceModel], 
            rule.TargetModel,
        )
    }
    
    // 添加 fallback
    for source, target := range config.Fallback {
        mappingGraph[source] = append(mappingGraph[source], target)
    }
    
    // 使用 DFS 检测环
    visited := make(map[string]bool)
    recStack := make(map[string]bool)
    
    for model := range mappingGraph {
        if detectCycle(model, mappingGraph, visited, recStack) {
            return fmt.Errorf("循环引用检测到: 从 %s 开始存在环", model)
        }
    }
    
    return nil
}

func detectCycle(model string, graph map[string][]string, visited, recStack map[string]bool) bool {
    visited[model] = true
    recStack[model] = true
    
    for _, target := range graph[model] {
        if !visited[target] {
            if detectCycle(target, graph, visited, recStack) {
                return true
            }
        } else if recStack[target] {
            return true // 发现环
        }
    }
    
    recStack[model] = false
    return false
}
```

**检测策略**：
- 配置保存时执行验证
- 检测到循环 → 拒绝保存 + 提示用户
- 配置加载时再次验证（防止直接修改数据库）
- 运行时不执行循环检测（性能考虑）

### 条件匹配逻辑

对于规则中的 `conditions` 数组：

```json
{
  "conditions": [
    {"param": "temperature", "operator": ">", "value": 0.8},
    {"param": "max_tokens", "operator": ">=", "value": 4000}
  ]
}
```

**匹配条件**：`temperature > 0.8 AND max_tokens >= 4000`

- 所有条件都满足 → 规则匹配成功
- 任意一个条件不满足 → 规则匹配失败

### 多规则优先级示例

```json
{
  "version": 2,
  "rules": [
    {
      "source_model": "gpt-4",
      "conditions": [
        {"param": "temperature", "operator": ">", "value": 0.8}
      ],
      "target_model": "gpt-4-turbo-high-temp",
      "priority": 1
    },
    {
      "source_model": "gpt-4",
      "conditions": [
        {"param": "max_tokens", "operator": ">", "value": 8000}
      ],
      "target_model": "gpt-4-32k",
      "priority": 2
    },
    {
      "source_model": "gpt-4",
      "target_model": "gpt-4-default",
      "priority": 999
    }
  ]
}
```

**匹配场景**：

1. 请求：`temperature=0.9, max_tokens=10000`
   - 优先级1规则：`temperature > 0.8` ✓ → 返回 `gpt-4-turbo-high-temp`

2. 请求：`temperature=0.5, max_tokens=10000`
   - 优先级1规则：`temperature > 0.8` ✗
   - 优先级2规则：`max_tokens > 8000` ✓ → 返回 `gpt-4-32k`

3. 请求：`temperature=0.5, max_tokens=4000`
   - 优先级1规则：✗
   - 优先级2规则：✗
   - 优先级999规则：无条件 ✓ → 返回 `gpt-4-default`

## 向后兼容

### 自动识别机制

系统会自动检测配置格式：

**V1 格式识别**：
```json
{
  "gpt-4": "gpt-4-turbo"
}
```
- 无 `version` 字段
- 或 `version != 2`
- 使用现有的 V1 映射逻辑

**V2 格式识别**：
```json
{
  "version": 2,
  "rules": [...]
}
```
- 有 `version: 2` 字段
- 使用新的 V2 规则引擎

### 混合使用

V2 配置中的 `fallback` 字段可以使用 V1 格式作为兜底：

```json
{
  "version": 2,
  "rules": [
    {
      "source_model": "gpt-4",
      "conditions": [{"param": "temperature", "operator": ">", "value": 0.8}],
      "target_model": "gpt-4-turbo"
    }
  ],
  "fallback": {
    "gpt-4": "gpt-4o",
    "claude-3": "claude-3-sonnet"
  }
}
```

## 实现要点

### 核心模块

1. **配置解析器**（`relay/helper/model_mapping_v2.go`）
   - 解析 V2 JSON 配置
   - 验证配置合法性

2. **参数提取器**（使用 `gjson`）
   - 从 `GeneralOpenAIRequest` 提取参数值
   - 支持多层路径解析
   - 自动处理 `json.RawMessage` 类型

3. **条件匹配器**
   - 实现各种运算符逻辑
   - 类型安全的值比较

4. **规则引擎**
   - 优先级排序
   - 条件 AND 逻辑
   - fallback 机制

### 技术选型

**方案：反射 + 类型断言（推荐）**

不使用 `gjson`，而是直接通过反射和路径解析来访问结构体字段：

```go
// 参数提取器
type ParamExtractor struct {
    request interface{}
}

// 提取参数值，返回 (值, 是否存在, 错误)
func (e *ParamExtractor) Get(path string) (value interface{}, exists bool, err error) {
    parts := strings.Split(path, ".")
    current := reflect.ValueOf(e.request)
    
    // 如果是指针，解引用
    if current.Kind() == reflect.Ptr {
        if current.IsNil() {
            return nil, false, nil
        }
        current = current.Elem()
    }
    
    for _, part := range parts {
        // 处理结构体字段
        if current.Kind() == reflect.Struct {
            field := current.FieldByName(part)
            if !field.IsValid() {
                // 尝试通过 JSON tag 查找
                field = findFieldByJSONTag(current, part)
                if !field.IsValid() {
                    return nil, false, nil // 字段不存在
                }
            }
            current = field
        } else {
            return nil, false, fmt.Errorf("cannot access field %s on non-struct", part)
        }
        
        // 处理指针类型
        if current.Kind() == reflect.Ptr {
            if current.IsNil() {
                return nil, false, nil // 指针为 nil
            }
            current = current.Elem()
        }
        
        // 处理 json.RawMessage（需要反序列化）
        if current.Type() == reflect.TypeOf(json.RawMessage{}) {
            rawMsg := current.Interface().(json.RawMessage)
            if len(rawMsg) == 0 {
                return nil, false, nil
            }
            // 递归解析 RawMessage 的剩余路径
            // ... (需要额外逻辑)
        }
    }
    
    return current.Interface(), true, nil
}

// 通过 JSON tag 查找字段
func findFieldByJSONTag(v reflect.Value, jsonName string) reflect.Value {
    t := v.Type()
    for i := 0; i < t.NumField(); i++ {
        field := t.Field(i)
        tag := field.Tag.Get("json")
        if tag == "" {
            continue
        }
        // 解析 json tag (去掉 omitempty 等)
        tagName := strings.Split(tag, ",")[0]
        if tagName == jsonName {
            return v.Field(i)
        }
    }
    return reflect.Value{}
}
```

**优点**：
- ✅ 编译期类型检查（对已知字段）
- ✅ 可以区分"不存在"、"nil" 和"零值"
- ✅ 返回 `exists` 标志，支持 `exists`/`not_exists` 运算符
- ✅ 类型安全

**缺点**：
- 实现复杂度较高
- 对于 `json.RawMessage` 需要特殊处理

---

**混合方案：反射 + gjson（推荐用于生产）**

```go
type ParamValue struct {
    Value  interface{}
    Exists bool  // 参数是否存在且非 nil
}

func ExtractParam(request *dto.GeneralOpenAIRequest, path string) ParamValue {
    parts := strings.Split(path, ".")
    
    // 第一层：使用反射直接访问结构体字段
    firstPart := parts[0]
    v := reflect.ValueOf(request).Elem()
    field := findFieldByJSONTag(v, firstPart)
    
    if !field.IsValid() {
        return ParamValue{Exists: false}
    }
    
    // 如果是指针类型
    if field.Kind() == reflect.Ptr {
        if field.IsNil() {
            return ParamValue{Exists: false} // nil 视为不存在
        }
        field = field.Elem()
    }
    
    // 如果只有一层路径，直接返回
    if len(parts) == 1 {
        return ParamValue{Value: field.Interface(), Exists: true}
    }
    
    // 多层路径：如果是 json.RawMessage，使用 gjson
    if field.Type() == reflect.TypeOf(json.RawMessage{}) {
        rawMsg := field.Interface().(json.RawMessage)
        if len(rawMsg) == 0 {
            return ParamValue{Exists: false}
        }
        
        // 使用 gjson 解析剩余路径
        remainPath := strings.Join(parts[1:], ".")
        result := gjson.GetBytes(rawMsg, remainPath)
        if !result.Exists() {
            return ParamValue{Exists: false}
        }
        return ParamValue{Value: result.Value(), Exists: true}
    }
    
    // 如果是结构体，递归处理
    if field.Kind() == reflect.Struct {
        // 递归解析子字段（类似上面的逻辑）
        // ...
    }
    
    return ParamValue{Exists: false}
}
```

**优点**：
- ✅ 第一层字段类型安全（编译期检查）
- ✅ 可以区分"不存在/nil" 和"零值"
- ✅ 对于深层嵌套使用 gjson 提高开发效率
- ✅ 返回结构化信息（Exists 标志）

```go
// 日志辅助结构
type MappingLog struct {
    ChannelID      int                    `json:"channel_id"`
    UserID         int                    `json:"user_id,omitempty"`
    OriginalModel  string                 `json:"original_model"`
    MappedModel    string                 `json:"mapped_model"`
    MappingVersion int                    `json:"mapping_version"`
    MatchedRule    *RuleMatchLog          `json:"matched_rule,omitempty"`
    EvaluatedRules []RuleEvaluationLog    `json:"evaluated_rules,omitempty"`
    FallbackUsed   bool                   `json:"fallback_used"`
    RequestParams  map[string]interface{} `json:"request_params,omitempty"`
}

type RuleMatchLog struct {
    RuleIndex          int                  `json:"rule_index"`
    Priority           int                  `json:"priority"`
    Description        string               `json:"description,omitempty"`
    ConditionsMatched  []ConditionMatchLog  `json:"conditions_matched"`
}

type ConditionMatchLog struct {
    Param       string      `json:"param"`
    Operator    string      `json:"operator"`
    ExpectedVal interface{} `json:"value,omitempty"`
    ActualVal   interface{} `json:"actual_value"`
    Result      bool        `json:"result"`
    Reason      string      `json:"reason,omitempty"`
}

type RuleEvaluationLog struct {
    RuleIndex         int                  `json:"rule_index"`
    Description       string               `json:"description,omitempty"`
    Matched           bool                 `json:"matched"`
    FailedConditions  []ConditionMatchLog  `json:"failed_conditions,omitempty"`
}

// 映射函数中的日志记录
func applyModelMappingV2(config *MappingConfigV2, request *dto.GeneralOpenAIRequest, info *common.RelayInfo) error {
    log := MappingLog{
        ChannelID:      info.ChannelId,
        OriginalModel:  info.OriginModelName,
        MappingVersion: 2,
    }
    
    // 收集请求参数（用于日志）
    log.RequestParams = extractRequestParamsForLog(request)
    
    // 筛选匹配的规则
    matchedRules := filterRulesBySourceModel(config.Rules, info.OriginModelName)
    
    // 遍历规则
    for i, rule := range matchedRules {
        ruleLog := RuleEvaluationLog{
            RuleIndex:   i,
            Description: rule.Description,
        }
        
        // 评估所有条件
        allConditionsMet := true
        var conditionLogs []ConditionMatchLog
        
        for _, condition := range rule.Conditions {
            condLog := evaluateCondition(condition, request)
            conditionLogs = append(conditionLogs, condLog)
            
            if !condLog.Result {
                allConditionsMet = false
                ruleLog.FailedConditions = append(ruleLog.FailedConditions, condLog)
            }
        }
        
        if allConditionsMet {
            // 规则匹配成功
            log.MappedModel = rule.TargetModel
            log.MatchedRule = &RuleMatchLog{
                RuleIndex:         i,
                Priority:          rule.Priority,
                Description:       rule.Description,
                ConditionsMatched: conditionLogs,
            }
            
            logger.Info("模型映射成功", "log", log)
            info.UpstreamModelName = rule.TargetModel
            info.IsModelMapped = true
            return nil
        }
        
        // 记录未匹配的规则（DEBUG级别）
        ruleLog.Matched = false
        log.EvaluatedRules = append(log.EvaluatedRules, ruleLog)
    }
    
    // 所有规则都不匹配，尝试 fallback
    if targetModel, exists := config.Fallback[info.OriginModelName]; exists {
        log.MappedModel = targetModel
        log.FallbackUsed = true
        logger.Info("模型映射：使用fallback", "log", log)
        info.UpstreamModelName = targetModel
        info.IsModelMapped = true
        return nil
    }
    
    // 无匹配，使用原模型
    log.MappedModel = info.OriginModelName
    logger.Debug("模型映射：无匹配规则", "log", log)
    return nil
}

// 评估单个条件并生成日志
func evaluateCondition(condition Condition, request *dto.GeneralOpenAIRequest) ConditionMatchLog {
    condLog := ConditionMatchLog{
        Param:    condition.Param,
        Operator: condition.Operator,
    }
    
    // 提取参数值
    paramValue := ExtractParam(request, condition.Param)
    condLog.ActualVal = paramValue.Value
    
    // 参数不存在或为 nil，直接返回不匹配
    if !paramValue.Exists {
        condLog.Result = false
        condLog.Reason = "参数不存在或为nil"
        return condLog
    }
    
    // 根据运算符评估
    switch condition.Operator {
    case ">":
        condLog.ExpectedVal = condition.Value
        condLog.Result = compareGreaterThan(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不满足 > %v", paramValue.Value, condition.Value)
        }
        
    case ">=":
        condLog.ExpectedVal = condition.Value
        condLog.Result = compareGreaterThanOrEqual(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不满足 >= %v", paramValue.Value, condition.Value)
        }
        
    case "<":
        condLog.ExpectedVal = condition.Value
        condLog.Result = compareLessThan(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不满足 < %v", paramValue.Value, condition.Value)
        }
        
    case "<=":
        condLog.ExpectedVal = condition.Value
        condLog.Result = compareLessThanOrEqual(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不满足 <= %v", paramValue.Value, condition.Value)
        }
        
    case "==":
        condLog.ExpectedVal = condition.Value
        condLog.Result = compareEqual(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不等于 %v", paramValue.Value, condition.Value)
        }
        
    case "!=":
        condLog.ExpectedVal = condition.Value
        condLog.Result = !compareEqual(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 等于 %v", paramValue.Value, condition.Value)
        }
        
    case "in":
        condLog.ExpectedVal = condition.Value
        condLog.Result = valueInArray(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 不在 %v 中", paramValue.Value, condition.Value)
        }
        
    case "not_in":
        condLog.ExpectedVal = condition.Value
        condLog.Result = !valueInArray(paramValue.Value, condition.Value)
        if !condLog.Result {
            condLog.Reason = fmt.Sprintf("%v 在 %v 中", paramValue.Value, condition.Value)
        }
        
    default:
        condLog.Result = false
        condLog.Reason = fmt.Sprintf("不支持的运算符: %s", condition.Operator)
    }
    
    return condLog
}
```

#### 保存时验证

```go
func ValidateMappingConfigV2(configJSON string) error {
    var config MappingConfigV2
    if err := json.Unmarshal([]byte(configJSON), &config); err != nil {
        return fmt.Errorf("JSON格式错误: %w", err)
    }
    
    if config.Version != 2 {
        return fmt.Errorf("version 必须为 2，当前为: %d", config.Version)
    }
    
    // 验证规则
    for i, rule := range config.Rules {
        if rule.SourceModel == "" {
            return fmt.Errorf("规则[%d]: source_model 不能为空", i)
        }
        if rule.TargetModel == "" {
            return fmt.Errorf("规则[%d]: target_model 不能为空", i)
        }
        
        // 验证条件
        for j, cond := range rule.Conditions {
            if cond.Param == "" {
                return fmt.Errorf("规则[%d].条件[%d]: param 不能为空", i, j)
            }
            
            // 验证运算符
            validOps := []string{">", ">=", "<", "<=", "==", "!=", "in", "not_in", "exists", "not_exists"}
            if !contains(validOps, cond.Operator) {
                return fmt.Errorf("规则[%d].条件[%d]: 不支持的运算符 '%s'", i, j, cond.Operator)
            }
            
            // 验证 value 必填性
            if cond.Operator != "exists" && cond.Operator != "not_exists" {
                if cond.Value == nil {
                    return fmt.Errorf("规则[%d].条件[%d]: 运算符 '%s' 需要提供 value", i, j, cond.Operator)
                }
            }
        }
    }
    
    // 验证 fallback
    for source, target := range config.Fallback {
        if source == "" || target == "" {
            return fmt.Errorf("fallback 中的模型名不能为空")
        }
    }
    
    // 循环检测
    if err := detectCycleInConfig(&config); err != nil {
        return fmt.Errorf("配置存在循环引用: %w", err)
    }
    
    return nil
}
```

## 性能考虑

### 是否需要缓存？

**结论：不需要缓存配置解析结果**

**原因分析**：

1. **JSON 解析性能已经足够**
   - 典型 V2 配置大小：1-10KB
   - `json.Unmarshal` 耗时：< 100μs
   - 相比整个请求处理（网络I/O、模型推理），可以忽略不计

2. **缓存带来的复杂度**
   - 需要缓存失效机制（渠道更新时）
   - 需要处理并发竞态（读写锁）
   - 需要管理缓存生命周期
   - 增加内存占用

3. **现有架构已有缓存**
   - 渠道信息本身已经被缓存（`model.Channel` 对象）
   - `ModelMapping` 字段（`*string`）已经在内存中
   - 只需要每次解析 JSON 字符串

### 性能优化策略（无缓存方案）

**推荐实现**：

```go
func applyModelMappingV2(mappingJSON string, request *dto.GeneralOpenAIRequest, info *common.RelayInfo) error {
    // 1. 快速路径：空配置直接返回
    if mappingJSON == "" || mappingJSON == "{}" {
        return nil
    }
    
    // 2. 解析配置（每次重新解析，性能影响可忽略）
    var config MappingConfigV2
    if err := json.Unmarshal([]byte(mappingJSON), &config); err != nil {
        // 解析失败，记录错误，使用原模型
        logger.Error("模型映射配置解析失败", "channel_id", info.ChannelId, "error", err)
        return nil
    }
    
    // 3. 筛选匹配源模型的规则
    var matchedRules []Rule
    for _, rule := range config.Rules {
        if rule.SourceModel == info.OriginModelName {
            matchedRules = append(matchedRules, rule)
        }
    }
    
    // 4. 快速路径：无匹配规则，尝试 fallback
    if len(matchedRules) == 0 {
        if targetModel, exists := config.Fallback[info.OriginModelName]; exists {
            info.UpstreamModelName = targetModel
            info.IsModelMapped = true
        }
        return nil
    }
    
    // 5. 按优先级排序
    sort.Slice(matchedRules, func(i, j int) bool {
        pi := matchedRules[i].Priority
        pj := matchedRules[j].Priority
        if pi == 0 {
            pi = 999
        }
        if pj == 0 {
            pj = 999
        }
        return pi < pj
    })
    
    // 6. 遍历规则，评估条件
    for _, rule := range matchedRules {
        if evaluateRule(rule, request) {
            info.UpstreamModelName = rule.TargetModel
            info.IsModelMapped = true
            return nil
        }
    }
    
    // 7. 所有规则都不匹配，尝试 fallback
    if targetModel, exists := config.Fallback[info.OriginModelName]; exists {
        info.UpstreamModelName = targetModel
        info.IsModelMapped = true
    }
    
    return nil
}
```

**优化点**：

1. **快速路径优先**
   - 空配置 → 直接返回
   - 无匹配规则 → 跳过条件评估
   - 无条件规则 → 直接匹配

2. **懒加载参数**
   - 只在需要时提取参数值
   - 避免提取未使用的参数

3. **避免重复序列化**
   - 不要在每个条件评估时都序列化请求
   - 按需提取单个字段

**预期性能**（单个请求）：

| 场景 | 耗时 | 说明 |
|------|------|------|

### 为什么不需要缓存

**数据支撑**：

假设系统配置：
- QPS: 10,000 请求/秒
- JSON 解析耗时: 100μs/次
- CPU 占用: 10,000 × 0.0001s = 1 CPU秒/秒 = 1 核心

**结论**：
- 1万 QPS 只需要 1 个 CPU 核心用于 JSON 解析
- 现代服务器通常有 8-32 核心
- JSON 解析的 CPU 占用 < 10%

**缓存的代价**：
- 代码复杂度增加 30%+
- 需要维护缓存失效逻辑
- 需要处理并发安全
- 需要处理缓存一致性

**性价比**：不值得为了 < 100μs 的优化引入缓存复杂度

### 零值处理规范

**重要**：必须严格区分两种情况：

1. **参数不存在或为 nil**：字段在请求 JSON 中不存在，或指针为 nil
   - `ExtractParam` 返回 `Exists: false`
   - 所有条件判断返回 false（规则不匹配）

2. **参数存在且有值**：字段存在且有值（包括零值如 `0`、`false`）
   - `ExtractParam` 返回 `Exists: true, Value: <actual_value>`
   - 值比较运算符正常工作

**示例**：

```json
// 请求1: {}
// temperature 不存在
ExtractParam("temperature") → {Exists: false}
条件 "temperature > 0.8" → false（跳过）

// 请求2: {"temperature": null}
// temperature 为 null（反序列化后指针为 nil）
ExtractParam("temperature") → {Exists: false}
条件 "temperature > 0.8" → false（跳过）

// 请求3: {"temperature": 0.0}
// temperature 存在且值为 0.0
ExtractParam("temperature") → {Exists: true, Value: 0.0}
条件 "temperature > 0.8" → false（0.0 不满足 > 0.8）
```

**匹配行为**：

| 条件 | 请求1（不存在） | 请求2（nil） | 请求3（0.0） | 请求4（0.9） |
|------|----------------|-------------|-------------|-------------|
| `temperature > 0.8` | ✗ (不存在) | ✗ (nil) | ✗ (0.0 ≤ 0.8) | ✓ (0.9 > 0.8) |
| `temperature == 0.0` | ✗ (不存在) | ✗ (nil) | ✓ (精确匹配) | ✗ (0.9 ≠ 0.0) |
| `temperature < 0.3` | ✗ (不存在) | ✗ (nil) | ✓ (0.0 < 0.3) | ✗ (0.9 ≥ 0.3) |

**简化逻辑**：参数不存在或为 nil 时，直接跳过该规则，无需复杂的存在性判断。

## FAQ

### Q1: V2 配置会影响性能吗？

**不会显著影响**。

- JSON 解析耗时 < 100μs（0.1毫秒）
- 条件匹配是内存操作，耗时 < 100μs
- 总耗时 < 500μs，相比网络I/O（几十到几百毫秒）可忽略

**数据**：1万 QPS 只需要 1 个 CPU 核心用于映射逻辑。

**不需要缓存**：每次重新解析 JSON 性能已足够，避免缓存带来的复杂度（失效机制、并发安全、一致性问题）。

### Q2: V2 支持链式映射吗？

**不支持**。V2 设计为单次映射，原因：
1. 条件映射的链式行为难以理解（第二次映射的条件如何判断？）
2. 避免不必要的复杂度
3. 配置清晰性（直接写最终目标模型更明确）

如果需要类似效果，在配置中直接指定最终模型：
```json
{
  "version": 2,
  "rules": [
    {
      "source_model": "gpt-4",
      "conditions": [{"param": "temperature", "operator": ">", "value": 0.8}],
      "target_model": "gpt-4-final"  // 直接写最终模型，不要写中间模型
    }
  ]
}
```

### Q3: 如何调试映射规则？

建议：
1. 添加详细的 `description` 字段
2. 在日志中记录匹配的规则和原因
3. 提供管理界面查看映射统计

### Q4: 条件中的参数不存在会怎样？

参数不存在或为 nil 时，该条件直接判定为 false（不匹配），继续尝试下一条规则。不会报错。

**示例**：
```json
{
  "conditions": [
    {"param": "temperature", "operator": ">", "value": 0.8}
  ]
}
```

- 请求中有 `temperature: 0.9` → 条件满足 ✓
- 请求中无 `temperature` 字段 → 条件不满足 ✗（规则跳过）
- 请求中 `temperature: null` → 条件不满足 ✗（规则跳过）

这是简化的设计，用户不需要显式写 `exists` 条件来判断参数是否存在。

### Q5: 可以同时匹配多个规则吗？

不会。匹配到第一个符合条件的规则后立即返回（单次映射）。通过 `priority` 控制匹配顺序。

V2 不支持链式映射，映射一次后立即返回结果。
