# Doubao / Seedance 视频计费价格表

> 适用范围：`relay/channel/task/doubao`（渠道名 `doubao-video`）
> 代码位置：[`relay/channel/task/doubao/constants.go`](../../relay/channel/task/doubao/constants.go)
> 最后核对：2026-10-13

本文档描述视频生成的**计费倍率折算规则**与**当前支持的模型-分辨率-有无视频组合**。

***

## 一、计费模型（必读）

### 1.1 计费基准约定

管理员在后台「模型倍率 / 模型价格」中配置的费率，**约定为「480p/720p + 不含视频」的标准价**。

系统以此为锚点，自动折算其它「分辨率档位 × 有无视频输入」的组合。

### 1.2 倍率公式

`EstimateBilling` 返回**单个**倍率（键名 `video_input`）：

```
倍率 = 目标价 / 基准档(720p)不含视频价
```

其中「目标价」按请求是否含视频输入决定取哪一列：

| 请求     | 目标价取值           |
| ------ | --------------- |
| 含视频输入  | 该分辨率档的**含视频价**  |
| 不含视频输入 | 该分辨率档的**不含视频价** |

分母固定取**基准档 720p 的不含视频价**，它与管理员配置的基准价代表同一个值，因此：

```
最终扣费 = 管理员配置的基准价 × 倍率 = 该档目标价（绝对价）
```

> **说明**：键名 `video_input` 是历史命名，其值已包含分辨率因素，并非单纯的视频输入折扣。

### 1.3 关键设计点

- **分母必须取基准档**：若误取「当前档的不含视频价」，分辨率溢价会在约分中被消掉，导致 1080p 按 720p 价格计费。
- **价格表非单调**：`doubao-seedance-2-0-260128` 的 4k 档（26）低于 720p 档（46），因此不能假设"分辨率越高越贵"，基准档必须显式配置。
- **查表用原始模型名**：`EstimateBilling` 按 `OriginModelName` 查表，与基础费率（`ModelPriceHelperPerCall`）保持一致，不使用渠道映射后的上游模型名。
- **未配置即返回 nil**：模型或分辨率档未配置时返回 `nil`，不附加任何倍率，走管理员配置的基础费率；基准档缺失或非正时同样返回 `nil`（避免除以 0 产生 `+Inf` 导致预扣费失控）。

## 三、支持的分辨率入参

分辨率经 `NormalizeResolution` 归一化，**大小写不敏感**，支持以下写法：

| 标准档位    | 接受的别名                               |
| ------- | ----------------------------------- |
| `480p`  | `480p` / `480` / `sd`               |
| `720p`  | `720p` / `720` / `hd`               |
| `1080p` | `1080p` / `1080` / `fhd` / `fullhd` |
| `4k`    | `4k` / `2160p` / `uhd`              |

**额外规则**：纯数字入参会按数值推断档位（≤3 位 → 480p；以 `1` 开头 → 1080p；其余 → 4k）。

> ⚠️ **不接受** **`2k`**：2K 是 2048×1080 的 DCI 规格，与 1080p（1920×1080）不是同一档，混用会导致计价档位错误。
> ⚠️ **不支持尺寸（WxH）**：Doubao 的分辨率入参是档位标识，不是 `1920x1080` 这类尺寸。

分辨率从两条路径解析（二者都归一到 `metadata.resolution`）：

- **OpenAI 兼容路径**：`/v1/videos` 的 `metadata.resolution`
- **Ark 原生路径**：`/api/v3/contents/generations/tasks` 的根级 `resolution` / `metadata.resolution` / `content[].resolution`

> **分辨率是计价的必要输入**：解析不到时请求在校验阶段直接返回 `400 invalid_resolution`，不会进入计费。

***

## 四、视频输入识别

`hasVideoInput` 为 `true` 的条件（满足任一）：

- `metadata.content[]` 中存在 `type == "video_url"` 的条目（Ark 原生格式）
- `metadata.video_url` 扁平字段存在

> **注意**：仅含 `image_url`（图片输入）**不算**视频输入，按"不含视频"计价。

## 五、如何添加新模型 / 新分辨率档

### 5.1 添加一个模型的价格配置

**唯一必改位置**：[`relay/channel/task/doubao/constants.go`](../../relay/channel/task/doubao/constants.go) 的 `videoPriceMap`。

在 `videoPriceMap` 中新增一项，**必须包含基准档** **`Resolution720P`**（否则该模型所有请求都会因基准档缺失而返回 `nil`，完全不计分辨率/视频费）：

```go
// doubao-seedance-3.0
//   720p    ：不含视频 90.00，含视频 54.00
//   1080p   ：不含视频 99.00，含视频 59.00
"doubao-seedance-3-0-260101": {
    Resolution720P:  {90.0, 54.0},   // ← 基准档，必须配置
    Resolution1080P: {99.0, 59.0},
},
```

格式为 `分辨率档位: {不含视频价, 含视频价}`，价格单位与官方定价一致（元 / 百万 tokens）。

### 5.2 添加一个新分辨率档位

1. 在 `constants.go` 的 `const` 块中新增档位常量：

```go
// Resolution2K 输出视频分辨率 2k
Resolution2K = "2k"
```

1. 在 `resolutionAliases` 中登记该档位及其别名：

```go
"2k": Resolution2K,
```

1. 在各模型的价格表中按需添加该档位的价格。

### 5.3 模型列表 `ModelList`（当前对展示无实际作用）

在 `constants.go` 的 `ModelList` 中登记模型名：

```go
var ModelList = []string{
    // ...
    "doubao-seedance-3-0-260101",
}
```

> ⚠️ **修改 `ModelList` 目前不影响前端可选模型列表**（原因见下方「`ModelList` 当前不被消费」）。保留它的意义在于与其它渠道适配器保持结构一致、便于日后接入展示链路。
>
> **计费与 `ModelList` 无关**：`EstimateBilling` 只查 `videoPriceMap`。新增模型若希望参与分辨率/视频计费，**必须**修改 `videoPriceMap`。

> ⚠️ **`videoPriceMap`** **无需与** **`ModelList`** **保持一致**，二者是独立数据：
>
> - 只加 `videoPriceMap` 不加 `ModelList` → 计费生效（如 `doubao-seedance-2-0-mini-260615`）
> - 只加 `ModelList` 不加 `videoPriceMap` → 模型可用，但**不计分辨率/视频费**（`EstimateBilling` 返回 `nil`，走基础费率）

#### 当前两者的不一致情况（截至 2026-10-13）

经核对源码，`ModelList`（`constants.go:5`）与 `videoPriceMap` 的成员如下：

| 模型名 | `ModelList` | `videoPriceMap` |
|---|---|---|
| `doubao-seedance-2-0-260128` | ✅ | ✅ |
| `doubao-seedance-2-0-fast-260128` | ✅ | ✅ |
| `doubao-seedance-2-5-260628` | ❌ | ✅ |
| `doubao-seedance-2-0-mini-260615` | ❌ | ✅ |
| `doubao-seedance-1-0-pro-250528` | ✅ | ❌ |
| `doubao-seedance-1-0-lite-t2v` | ✅ | ❌ |
| `doubao-seedance-1-0-lite-i2v` | ✅ | ❌ |
| `doubao-seedance-1-5-pro-251215` | ✅ | ❌ |

> 未配置 `videoPriceMap` 价格的模型走 `EstimateBilling` 返回 `nil` 的路径，按管理员配置的**基础费率**计费，不受本价格表影响。

#### ⚠️ `ModelList` 当前不被消费（已核实）

`task/doubao` 的 `ModelList` 通过 `GetModelList()`（[`adaptor.go:532`](../../relay/channel/task/doubao/adaptor.go)）暴露，但**唯一消费者** [`controller/model.go`](../../controller/model.go) 的两处调用（`init()` 的 `41` 行与 `106` 行）都用 **`relay.GetAdaptor(...)`**（同步渠道注册表），而 `GetAdaptor` **从不返回 `taskdoubao.TaskAdaptor`**——`taskdoubao` 在整个 [`relay/relay_adaptor.go`](../../relay/relay_adaptor.go) 中只出现在 `GetTaskAdaptor`（`159` 行）。

此外 `ChannelTypeDoubaoVideo`（54）在 [`common/api_type.go`](../../common/api_type.go) 的 `ChannelType2APIType` 中没有分支，[`model.go:97`](../../controller/model.go) 会得到 `success=false` 而 `continue` 跳过。

**因此：修改本文件的 `ModelList` 不会影响前端可选模型列表。** 该变量当前是死代码。

> 计费链路**不读** `ModelList`：它走 `GetTaskAdaptor` → `ChannelTypeDoubaoVideo` → `taskdoubao.TaskAdaptor`（[`relay_adaptor.go:158`](../../relay/relay_adaptor.go)），与上述展示链路相互独立。
>
> 这也解释了为何 `doubao-seedance-2-0-mini-260615` 不在 `ModelList` 中却仍能正常计费。
>
> Seedance 系列的渠道模型展示由 [`relay/channel/volcengine/constants.go`](../../relay/channel/volcengine/constants.go) 提供（其中登记了 `doubao-seedance-1-0-pro-250528`、`seedance-1-0-pro-250528` 等）。

### 5.4 管理后台必须同步配置

代码里的价格表**只是相对倍率**，实际扣费基数来自后台。新增模型时必须在后台配置：

- **模型价格（ModelPrice）**：按次计费时使用
- **模型倍率（ModelRatio）**：按量计费时使用

配置值应对应\*\*「480p/720p + 不含视频」的标准价\*\*，与 `videoPriceMap` 中的基准档保持一致。

> ⚠️ 若两者都未配置且开启自用模式，`GetModelRatio` 会静默兜底返回 `37.5`（[`setting/ratio_setting/model_ratio.go:420`](../../setting/ratio_setting/model_ratio.go)），可能导致意外扣费。

## 六、排查计费问题

`EstimateBilling` 在返回前会打印完整明细日志：

```
[Doubao Video] EstimateBilling: originModel=doubao-seedance-2-0-mini-260615,
upstreamModel=doubao-seedance-2-0-mini-260615, resolution=480p, hasVideoInput=true,
resolutionPriceWithoutVideo=23.00, resolutionPriceWithVideo=14.00,
baselineWithoutVideo=23.00, video_input=14/23=0.608696
```

| 字段                                                         | 含义                             |
| ---------------------------------------------------------- | ------------------------------ |
| `originModel`                                              | **实际查表**用的模型名（原始模型名）           |
| `upstreamModel`                                            | 渠道映射后的上游模型名，仅作对照               |
| `resolution`                                               | 归一化后的分辨率档位                     |
| `hasVideoInput`                                            | 是否识别到视频输入                      |
| `resolutionPriceWithoutVideo` / `resolutionPriceWithVideo` | 该分辨率档查到的两个价格（未使用的一列也打印，便于交叉核对） |
| `baselineWithoutVideo`                                     | 分母：基准档 720p 不含视频价              |
| `video_input`                                              | 分子/分母/最终倍率                     |

**网络日志中** **`计算参数：video_input: 0.61`** 是 `%.2f` 截断显示，实际计费用完整精度，以 `EstimateBilling` 日志为准。

### 6.1 预扣与结算

- **预扣**：任务提交时按预扣额度扣费。按量计费模式下预扣 = `modelRatio/2 × 500000 × groupRatio × 倍率`（`/2` 为保守折半，避免余额不足被拒）。
- **结算**：任务完成后，若上游返回 `usage.total_tokens`，按 `total_tokens × modelRatio × groupRatio × 倍率` 重算，**多退少补**（结算公式**不含** `/2`）。
